Layer 3: Governance

Scarp Governance Gateway

Independent governance gateway for enterprise AI agents. Every agent interaction is intercepted, classified, evaluated against policy, and decided in real time. Every decision produces a cryptographically signed evidence record the customer owns and any third party can verify.

Architecture

Where the gateway sits.

Scarp Governance Gateway operates as a stateless HTTPS proxy between agents and the AI providers, tools, and services they interact with. All traffic routes through the gateway. No agent reaches a provider or tool without producing a governed, signed evidence record.

All components deploy inside the customer's own infrastructure. The private signing key never enters the gateway process. There is no vendor copy of data, evidence, or telemetry.

Capabilities

Full governance surface.

Scarp Governance Gateway is a complete governance infrastructure, not an evidence tool. It classifies, evaluates, decides, and enforces before producing a signed evidence record. Every capability listed here is operational.

Content classification and DLP

PII, PHI, financial data, credentials, and adversarial content detected on every request. Redaction applied before content reaches the provider when policy requires it. Custom detection patterns supported.

Five-scope emergency controls

Immediate shutdown of governed agent activity at five granularity levels: global, provider, model, agent, and tool. Asymmetric authorization: instant activation, deliberate deactivation through the change advisory workflow.

Entity lifecycle management

Providers, models, agents, tools, system identities, and policies are registered entities with default-deny posture. An unregistered entity produces an immediate BLOCK with a machine-readable reason code.

Multi-dimensional policy evaluation

Policy composed across content classification, entity status, kill switch state, credential exposure, and adversarial signals in a single evaluation per action. Eight governance decision types: ALLOW, BLOCK, HOLD, ATTEST, TAMPERED, CHAIN_INTEGRITY_UNVERIFIABLE, HOLD_QUEUE_SATURATED, POLICY_EVALUATION_ERROR.

Multi-hop chain tracking

Every workflow receives a gateway-generated identifier that links all evidence packs in a multi-step agent chain. The identifier is generated solely by the gateway and never accepted from agents. Chain integrity is cryptographically verifiable across hops.

Change advisory workflow

Every change to governance configuration passes through a structured approval workflow. 27 administrative action types, each producing its own signed evidence record. The answer to "who governs the governance?"

Credential and adversarial detection

API keys, connection strings, tokens, and prompt injection attempts detected in real time. Adversarial content signals projected to the customer's monitoring infrastructure alongside the signed evidence record.

Budget enforcement

Per-action spending limits enforced at the governance layer. The budget is a governance constraint, not a provider-side billing limit.

Evidence independence

Evidence the customer owns and anyone can verify.

The structural property that separates Scarp Governance Gateway from every other governance system in the market. The evidence record belongs to the customer and stands on its own.

1
Signing

Customer-managed HSM, never the gateway.

Every evidence record is signed via the customer's own hardware security module. The private key never leaves the HSM. It never enters the gateway's process memory. The gateway calls the HSM Sign API through a service identity; it never holds, sees, or caches the raw key material.

2
Storage

Customer-controlled, write-once.

Evidence packs are stored in the customer's own infrastructure, one pack per record, write-once, never modified. The customer can remove the gateway entirely and retain every piece of governance evidence produced. The evidence is self-contained, portable, and verifiable without any operational dependency on the gateway operator.

3
Verification

Offline, independent, complete.

Any third party with the public key and the evidence pack can verify the record on their own machine. No server to reach. No account to create. No callback to anyone. Change one field and verification fails. The verifier is open source and deterministic.

4
No vendor copy

Zero telemetry. Zero aggregation.

There is no aggregation service. There is no telemetry sent to the gateway operator or any third party. No phone-home. No cross-tenant data movement. The customer's governance data stays inside the customer's boundary.

Open verifier

scarp-verify

The open-source standalone verifier that answers the one question the architecture turns on: can an outside party confirm a governance record without trusting whoever produced it?

Single-pack verification

Verifies the cryptographic signature and content integrity of any individual evidence pack. Change one field and it fails.

Batch verification

Verifies a corpus of evidence packs in a single pass. Reports per-pack and aggregate results.

Chain verification

Verifies multi-hop workflow chains across evidence packs using cryptographic hash linkage. Confirms the chain is intact and correctly ordered.

Zero dependencies

Static binary. Five platforms. No runtime, no framework, no network. Bring the pack and the public key. Run it on your machine.

Design boundary

Multi-agent coordination in V1.

Scarp Governance Gateway V1 governs agent interactions with tools and providers through the MCP protocol. Agents do not communicate directly with each other. When Agent A needs a result from Agent B, both interact through MCP tool servers, and each interaction produces its own governed, signed evidence record.

Eight open questions blocking direct A2A delegation.

Direct agent-to-agent delegation with governance preservation is V2 scope. Eight questions must be answered before it ships: liability attribution across organizational boundaries, cross-organizational trust establishment, delegation scope and constraint propagation, revocation propagation across agent chains, intent auditability for delegated actions, sensitivity ceiling inheritance, evidence chain continuity across trust domains, and policy reconciliation between organizations.

Each question maps to a specific Scarp substrate layer. Layer 3 (Governance) is shipped. The remaining questions sit in Layers 1 (Identity), 2 (Cooperation), and 4 (Settlement), and their answers are specified in the substrate architecture.

Architectural alignment, not certification or compliance advice. None of these frameworks were drafted with autonomous agents in mind. All carry an assumption that becomes load-bearing the moment agents take consequential actions: the entity under scrutiny cannot be the sole author of the evidence used to judge it.
